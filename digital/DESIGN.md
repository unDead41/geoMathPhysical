# GeoDecoder Digital Design System

## GeoMath entry preview — 4 November 2026

The approved GeoMath reference governs the four entry surfaces: Home, mode
selection, resume and how to play. The shared header is a single application
shell; the signature illustration is a real-time 3D geometry kit on a grid board,
with exact SVG alternatives when WebGL is unavailable. Original procedural assets
share bevels, satin materials, studio lighting and contact shadows. Three.js is
pinned and bundled locally; there are no remote model, texture or font requests.
Home uses a text/art hero with three equal action cards underneath. Mode choices
are native radio cards. Resume uses actual actor-scoped progress, and the guide
shows three reusable steps with explicit demonstration playback controls.

This preview extends Model B without changing the shared palette or adding a
second token owner. `dist/entry.css` consumes `design-system/tokens.mjs` through
the generated CSS. Its shell maximum uses `--page-max`; controls keep the existing
foundation recipes. `dist/entry-components.mjs` owns repeated card/guide markup,
`entry-copy.mjs` extends the existing catalog, and `entry-ui.mjs` binds those views.
New entry pages must extend these owners. See `docs/ENTRY_UI.md` for reuse.
`entry-models.mjs` owns the reusable presentation assets; `entry-scenes.mjs` owns
one shared renderer and the motion lifecycle. The established visual palettes
provide object colours. Interface colours continue to come from central tokens.
Rotation has labelled button alternatives to dragging. The existing animation
preference controls every decorative scene; hidden routes/background tabs stop
rendering. Cards gain gentle central-token elevation and a dedicated artwork
area while the same native radio/form/navigation owners retain all behaviour.
Other application surfaces and the pinned learning module retain their owners.

## Overview

### Creative North Star
A real classroom geometry kit translated into a bright digital workbench. The signature is the two scanner pads: R1 takes a solid, R2 takes its net. Exact SVG models serve learning and are never decorative AI geometry.

### Product context and register
Malaysian pupils/students, readable at Tingkatan1 level, using mouse,
keyboard or touch. BM is default with English available. Home groups Main,
Belajar and Akaun/Kelas; guest entry needs a nickname only. Quiz10, practice15
and missed-question review share one geometry workbench. Accounts/classrooms
and two-player Duel retain separate server rules. Preserve the physical kit
identity and exact solid/net illustrations.

### Token ownership/runtime mapping
Model B: `design-system/tokens.mjs` is the single authoring owner. The generator
`tools/design-tokens.mjs` emits `dist/design-tokens.css`, the plain offline module
adapter, module CSS and `dist/module-design.mjs`. This document mirrors accepted
brand values and explains their use. `dist/foundation.css` owns shared recipes;
`dist/module-foundation.css` adapts native learning controls. Existing feature CSS
owns layout and geometry, with no canonical token declarations.

`npm run design:check` verifies exact generated bytes and rejects competing token
owners. `tools/check.mjs` also compares the palette above. Full mapping, adoption
instructions and migration evidence: [central design system](docs/DESIGN_SYSTEM.md).
Primary text/focus and filled-action colors are separate semantic roles in dark
mode; use `--primary-fill` with `--on-primary-fill` for a filled action. Never
combine white text with the pale dark-mode text-primary token.

## Colors
Cool blue-white canvas, navy text, royal blue interaction. Mint indicates success; red errors; violet active hints. Per user request, solids and nets now use eight expressive palettes owned by `dist/visuals.mjs` and consumed by `art.mjs`. Five unique colours per shelf, changed for every shape each question. Solid/net colours differ for the same shape, so colour is not an answer cue. All status colours also have text.

## Typography
Trebuchet MS display headlines, Segoe UI body with system fallback, monospace clocks. Body line-height 1.65, short instructions 16px, headers 32–56px. No network fonts or font swaps.

## Layout
76rem maximum; desktop two-column entry and centred workbench. At 800px the registration/game panels stack, scanner pads remain paired when possible. Five choices wrap to three or two columns below 600px. Document scrolling owns all screens. Main actions at least 44px tall. Reserve question and feedback geometry.

## Elevation & Depth
Subtle cool shadows on the hero's scanner platform and dialog. Normal cards use borders, not heavy floating shadows. Svg solids use face colours to describe spatial depth.

## Shapes
16px standard corners, 24px large panels, 10px controls and 6px compact markers. Soft rectangles for physical pads, rounded rectangles for controls. Mathematical faces remain geometrically exact.

## Components

### Foundational visual states
Geometry-choice artwork may move inside its hit area; shared action targets stay fixed. Focus is a 3px blue outline; active selections use outline plus text; disabled reduces saturation and explains the stage. All feedback uses visible inline status and one live region. No skeleton loading for browser-local operations.

### Buttons and actions
Solid primary for start/replay/scan, outline neutral for secondary, outline danger for erase/leave. Labels describe actions. Icon buttons have accessible BM names. Minimum 44px height with content expansion for large text. Use solid danger for confirmed destructive actions and outline danger for secondary risk actions.

### Navigation and data display
Header keeps brand, Tetapan, Cara main and Papan skor. Settings groups
language, theme, audio, text size and animation. Home separates play, learning
and class accounts. The quiz board stays bounded to50 records with show-all.
Results show score/actions before expandable detailed analysis. Storage scope
and classroom/Duel authority remain explicit.

### Forms and overlays
All fields have visible labels, inline errors and first-error focus, no native validation bubbles. Category is a radio pair. Shared native `<dialog>` provides authored contents, modal inertness, Escape and restored focus. Confirm before abandoning an active round or erasing scores.

### Iconography
Small inline SVG icons, 1.8px strokes, 20–24px, text labels on primary controls. Brand cube uses geometric faces. Every geometric answer has an equivalent screen-reader description.

### Motion
R1/R2 feedback uses three 150ms ON/OFF cycles. Successful pairs advance after 900ms; wrong/skipped answers hold a correction until the player continues, with a minimum 1800ms reading interval. Hero objects float slowly, card artwork breathes 3px inside fixed hit areas, accepted models enter scanner pads, and correction pairs slide into place. No geometry morph is claimed; the full unfolding module is a separate branch task. The header motion control and system reduced-motion setting remove movement/flashing while preserving text and timing. Decorative perspective grids are clipped within the hero scene to prevent horizontal page overflow.

### Content and data visualization
BM, short specific instructions. No shape names printed on answer cards; use shuffled A–E identifiers with diagram descriptions for screen readers. Names are rendered as text, never trusted HTML. Time MM:SS; date ms-MY in Asia/Kuala_Lumpur.

## Do's and Don'ts

- Do keep all five solids and five nets visible.
- Do require R1 before R2 and grant one mark for a pair.
- Don't give the answer through matching card positions or colours.
- Don't rely on dragging, colour or sound alone.

Decoration is aria-hidden; text stays usable if clients simplify rounded shapes.

100/125/150% preference. Control borders meet 3:1 against their field surfaces;

## Visual help and tutorial (v2.8.0)

The shared helpVisual renderer reuses the application's exact cube solid/net SVGs
for the three R1, R2 and completed-pair steps. It is a fixed demonstration and
never projects a live answer. CSS runs one finite 4.8-second pass; a single
listener owns Pause/Resume and Replay for both help and tutorial. These controls
change the demonstration only. OS or application reduced motion uses a labelled
static illustration, with no external video or automatic audio. Seven task
guides put the visual first and disclose full text and keyboard instructions on
request. Existing dialog focus, Escape, report exports and game clocks retain
their owners.

## Module v1.6.0 learning surfaces

Studio Pelan & Dongakan uses the module's actual learning meshes and consistent
front/plan/right-view scale in the Kaedah 1 arrangement. Visible, hidden and
construction lines have distinct styles as well as labels. Line/circle tools,
coordinate forms, selection/delete and Undo provide alternatives to dragging;
three-view boards may scroll locally on phones. These are projections of a
closed object, separate from the existing unfolding activities.

Semakan Langkah Pengiraan presents four steps: formula, substitution, calculation
and unit. It reuses canonical measures and the current dimensions/π from notes,
with targeted feedback and optional worked examples. Neither new surface adds
scores or replaces the four formative reflections. Native BM/English roots follow
host settings, keep session drafts across ordinary navigation and clear drafts
when the account session changes. See module/DESIGN.md and module/UX-CONTRACT.md
for mathematical boundaries, draft ownership and accessibility details.
