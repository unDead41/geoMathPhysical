# ADR: Android foundation toolchain

Date: 4 November 2026. Status: accepted for the development foundation.

GeoMath starts with an Android-only native Flutter shell and a bundled local
WebView module. The scaffold was generated by the installed stable Flutter
3.47.9 SDK, framework `c197ca5199e9ee5661e865596c9c07294dfab51c`, with Dart
3.13.7. No iOS, web or desktop platform runner is included.

Keep the generated, supported Android build stack together: Android Gradle
Plugin 9.1.0, Gradle 9.3.1, Kotlin Gradle plugin 2.4.0 and Java 17. The Flutter
SDK supplies compile/target API 36, minimum API 24 and NDK 28.2.13676358. This
avoids copying historical SDK numbers from the planning archive. Flutter's
compatibility switches in `android/gradle.properties` are retained as generated.
Changing Flutter requires rechecking that stack and plugin compatibility.

`com.geomath.dev` is a development application ID and namespace; the display
name is GeoMath. This is not a registered store identity. App version starts at
`0.1.0+1` independently of the firmware version. Store signing and native Auth
callback registration belong to a later, explicitly configured release.

The current WebView, path-provider and preferences plugins require Android API
24+. Secure storage uses platform protection; Android backups are disabled to
avoid restoring encrypted session values without their device-bound keys.
Release Internet permission supports future configured HTTPS capabilities.
Cleartext traffic is disabled; the module loads trusted bundled assets directly.

Use SDK ChangeNotifier/Listenables and Flutter navigation for the shell. The
foundation reserves the following adapters: WebView, Supabase, SQLite,
protected storage, simple preferences and filesystem paths. Records and outbox
must be committed through SQLite transactions. `shared_preferences` is not a
durable-record contract and must not be used to claim critical records saved.
`sqflite_common_ffi` provides real SQLite host tests. Mobile plugin smoke tests
still need Android and do not become covered by host tests.

CI is scoped to this app and its workflow. It runs the same format, analyze,
unit/widget-test and debug-APK commands as local validation, followed by a real
API 36 emulator integration test. SDK/package caches contain dependencies only;
they do not contain app data or environment configuration. CI configuration
does not itself count as evidence of a successful run.
